# Module · Exemplars

> 供 P2–P5 在生成或审阅前按对应小节读取。以下是对历史资产机制的重新抽象示例，不复制旧 Prompt，不是完整 90 分 Narrative Plan。

## 1. 来源与使用边界

| 来源 | 只校准什么 | 不继承什么 |
|---|---|---|
| `桃子AI写爽文指令.txt` | 强冲突、悬念、反差的节奏意识 | 样例剧情、强刺激唯一论、爆款承诺 |
| `内容转1分钟剧本 v2.0.txt` | 多方案确认、受众/情绪、Hook 分类、结构选择 | 固定时长、最终台词、角色和镜头 |
| `AI猫微信文章.txt` | 日常共鸣、轻困扰—理解、陪伴感、低强度参与 | 个案内容、未经核验事实、原文表达 |
| `编剧.txt` | 人性取舍、反应/呼吸的功能意识 | 正式剧本、摄影、分镜、Seedance 参数 |

CR-001 后，Narrative Designer 不直接读取 `视频拆解.txt` 作为叙事模板；它只消费 `wenjing-video-reference-analyzer` 输出且通过 Gate 的 Transfer Rules。

## 2. Hook 正例与反例

### 正例：可兑现的决策钩子

```yaml
promise: "观众将理解为什么一个当时合理的管理选择后来产生了意外代价"
fact_refs: [FACT-03, FACT-07]
knowledge_refs: [KP-01]
required_payoff: "比较决策时信息与事后结果，解释边界而非嘲讽当事人"
```

为什么可用：承诺的是“理解机制”，不是未被证明的内幕；事实和知识锚明确。

### 反例：无锚的强刺激

```text
“所有人都被骗了，真正的幕后操盘者终于出现。”
```

打回：若 Truth Lock 没有欺骗和操盘者，这会新增人物、动机与因果；必须删除，不能只换措辞。

## 3. 策略比较正例

同一案例可以有实质不同的方案：

- A 决策—后果：让观众先选，再揭示约束与结果；适合训练管理判断。
- B 反差—重估：先呈现表面成功，再比较被忽略的长期指标；适合概念纠偏。
- C 共鸣—理解：从一线角色的日常困境进入制度机制；适合低门槛教学。

三者的 Hook、情绪终点和知识载体都不同，才算真方案。只把“悬念版/更悬念版/最悬念版”列成三项属于伪方案。

## 4. Narrative Node 正例与反例

### 正例

```yaml
node_id: NOD_03
narrative_function: CHOICE
entry_state: "观众只看到增长目标"
content_summary: "呈现已锁定的两个行动选项及共同资源约束"
exit_state: "观众意识到目标之间存在取舍"
fact_refs: [FACT-04, FACT-05]
knowledge_refs: [KP-02]
downstream_writing_task: "用可拍行动呈现选项和约束，不新增结果"
```

### 反例

```text
镜头推近经理愤怒的脸，他拍桌喊出完整台词；BGM 突然停止。
```

打回：这是表演、镜头、音乐和台词，越过 Narrative 边界。应只保留“节点需要显示决策压力升级”的功能。

## 5. 共鸣/治愈路线正例

当案例价值来自细微关系变化时，可用：熟悉处境 → 看见未被注意的约束 → 小行动改变互动 → 观众重新命名问题。

不要求反派、大反转或 10/10 高潮。Payoff 可以是“理解原本被误解的行为机制”，但仍需绑定事实与教学目标。

## 6. Participation 正例与反例

### 正例

在 Choice Node 提供两个都付出代价的真实选项，让观众先选择；Payoff 后再询问“你最初忽略了哪个约束”。互动直接服务 KP-02。

### 反例

在开头要求“同意的扣 1”，后文没有使用该判断。

打回：没有认知动作、没有教学连接，只是互动诱饵。

## 7. Reference 迁移正例与反例

### 正例

Reference 规则：原视频通过“先给直觉答案，再连续加入两个约束”形成重估。

本项目迁移：只采用“逐步暴露约束”的机制；约束内容完全来自当前 Truth Lock，重新设计节点，不沿用原视频的人物、问题措辞、事件顺序或结尾。

### 反例

把原视频的角色换名、行业换掉，但保留相同开场句、三次事件升级和独特结尾反转。

打回：这是结构性复制，不是机制迁移；G-RA-03 BLOCK。

### Transcript-only 反例

Reference 只有 transcript，却输出“快速推镜和鼓点在第 3 秒制造留存”。

打回：推镜和鼓点不可观察；Audiovisual 必须 `NOT_OBSERVABLE`，相关规则不得进入 Narrative。

## 8. Emotion / Knowledge 正例

```yaml
beat_id: BEAT-04
node_id: NOD_04
emotion_label: "重新评估"
relative_intensity: 6
change_trigger: "FACT-08 揭示前一选择的隐藏约束"
beat_function: "从责怪个人转向理解系统取舍"
knowledge_link: KP-02
```

数字只表示相对变化，不能声称观众真实情绪被精确测量。

## 9. 使用纪律

- 只读取当前 stage 对应小节，不整份复制进输出。
- 正例用于核对结构和边界，不作为固定答案。
- 反例命中时按打回理由修复。
- 当前没有完整 90 分 Narrative Plan；P9 用真实管理学案例生成并验证后，才可版本化补入完整示例。
