# 外部核验边界

> 只有在用户要求核实、核心缺口必须补料或高风险事实需要验证时加载。本模块不把 Case Planner 变成通用研究 Skill。

## 1. 默认模式

默认任务是“忠实整理用户提供材料”，不是判断整个案例在现实世界中是否真实。输出必须区分：

- `SOURCE_INTERNAL_PASS`：材料内部可追溯且无未解决冲突。
- `EXTERNALLY_VERIFIED`：另有独立来源核验。
- `UNVERIFIED_EXTERNALLY`：未进行或无法完成外部核验。

Truth Audit PASS 默认只代表第一种，不代表现实世界绝对真实。

## 2. 必须考虑外部核验的信号

- 用户明确说“查证、核实、确认真假、补充最新资料”。
- 材料涉及现实人物/组织的严重负面指控或声誉风险。
- 涉及法律、医疗、财务等高风险判断。
- 关键数字、政策、职位、产品参数或时效信息可能已变化。
- 核心事实缺口会改变教学结论，且用户希望补充而非保留 UNKNOWN。

若当前环境没有合适工具、网络或权限，应说明限制并输出 `REVIEW_REQUIRED`；不得伪装完成核验。

## 3. 核验流程

1. 将待核 claim 单独列入 Proposed External Check，不直接改 Fact Table。
2. 与用户确认核验范围；只查影响核心结论的最小集合。
3. 优先一手、官方或可审计来源；技术问题优先官方文档/论文。
4. 每个外部来源创建新 source_id 和完整 anchor。
5. 记录结果：SUPPORTED / CONTRADICTED / INCONCLUSIVE。
6. 回到 P2，由用户处理冲突或缺口；不静默覆盖原材料。

## 4. 外部信息进入 Truth Lock 的条件

必须同时满足：

- 来源身份清楚、anchor 可复核。
- 与原案例材料的关系已标明：补充、纠正、背景或争议。
- 用户知道这是外部补充，而非原文内容。
- 若改变核心教学方向，重新触发 P3 HARD Gate。

## 5. 不属于本 Skill 的请求

以下请求应停止当前业务并建议进入专门研究/事实核查流程：

- 对一个行业、公司或人物开展开放式深度调查。
- 系统性文献综述或全网资料聚合。
- 法律意见、医疗诊断或投资建议。
- 需要大量下载、数据库检索或专业取证的核查。

Case Planner 可以继承这些流程提供的已落盘核验报告，但不自行吞并其方法。
