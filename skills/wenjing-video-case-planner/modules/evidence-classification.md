# 证据分类规则

> P1–P2 按需加载。目的：让每个 claim 的身份明确，防止“听起来合理”被写成事实。

## 1. 四类声明

### FACT

来源直接陈述或可由来源中的明确数据直接计算，且 source anchor 支持相同强度的 claim。

例：材料写“项目于 2024 年 3 月启动” → 可记 FACT。若材料只写“2024 年春季”，不得强化成 3 月。

### INTERPRETATION

来源作者、受访者或教师对事实的解释、评价或理论归因。必须记录解释者，不写成无主体客观结论。

例：“管理层认为失败源于激励不足”是 FACT（确实表达了该看法）；“失败源于激励不足”是 INTERPRETATION。

### INFERENCE

系统或用户基于多个信息作出的推导，来源没有直接说出。必须列出推理依据和替代解释。

例：“员工可能因考核变化而降低投入”只能是 INFERENCE，除非材料有直接证据。

### UNKNOWN

材料缺失、互相冲突、语义含混或无法定位来源，不能可靠判断。

UNKNOWN 不是失败；它是阻止下游虚构的正式护栏。

## 2. 判定顺序

逐条提问：

1. 来源是否直接支持这句话？否 → INFERENCE 或 UNKNOWN。
2. 这句话是否只是某人的看法？是 → INTERPRETATION，并记录主体。
3. 措辞强度是否高于来源？是 → 降低强度或 UNKNOWN。
4. 是否混合多个 claim？是 → 拆分后分别分类。
5. 是否存在冲突来源？是 → 保留各自 claim，建立 ISSUE，不擅自择一。

## 3. 事实粒度

- 一行只含一个主体、一个主要动作/状态和必要条件。
- 因果必须拆为“事件 A”“事件 B”“来源是否明确声称 A 导致 B”。
- 数量、比例、时间范围、比较基准分别记录。
- “显著、主要、普遍、必然”等强词需要来源明确支持。

## 4. Confidence

Confidence 描述“当前材料对分类和措辞的支持程度”，不等于现实世界真伪：

- HIGH：直接、清楚、锚点稳定，且无冲突。
- MEDIUM：直接但上下文有限，或存在可解释歧义。
- LOW：间接、锚点弱或冲突未解决。

LOW FACT 不自动删除，但不得作为关键情节或教学结论的唯一依据。

## 5. 矛盾处理

建立 issue 时保留：

- issue_id
- 涉及的 fact_id/source_id
- 冲突类型：时间、数量、人物、行为、因果、评价或版本
- 对教学目标和戏剧化的影响
- A 保持 UNKNOWN / B 补充来源 / C 排除核心集
- 用户决定与理由

## 6. 禁止升级

以下内容不得升级为 FACT：

- 模型记忆或一般常识
- 没有来源的网络摘要
- 用户未确认的合理猜测
- 为补剧情而设计的动机、对白或场景
- 理论模型对案例的解释
- 仅因多次重复而显得可信的同源来源
