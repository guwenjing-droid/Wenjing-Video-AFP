# 用户核查清单 · Narrative Designer v0.1

> Skill 跑流程，用户拿本清单监督；人始终掌舵。每完成一个阶段再勾选，未满足阻断条件时不要输入 `Next`。

| 阶段 | Skill 应完成的动作 | 我怎么核查 | 应见落盘文件 |
|---|---|---|---|
| P0 | 校验项目、Truth Lock 和可选 Reference Analysis | Truth 必须 LOCKED 且版本/完整性一致；可选 Reference 缺失不阻断；transcript-only 不得出现视听判断 | `00_project_manifest.yaml`、`00_project_state.md` |
| P1 | 提取最小 Narrative Brief | 受众、教学目标、知识点、目标情绪和约束来源清楚；没有重写事实 | `02_narrative_plan_DRAFT.md` |
| P2 | 给出 2–3 个钩子/参与策略并等待选择 | 方案实质不同；Hook 有事实/知识锚与 Payoff；Reference 只提供抽象机制 | 更新后的 Draft + Decision Log |
| P3 | 形成 Narrative Nodes | 每个核心节点有进入/退出状态和锚；没有最终台词、场次、镜头或模型参数 | 更新后的 Draft |
| P4 | 映射情绪、反应、知识和参与 | 知识点全覆盖；情绪变化有依据；没有为了曲线新增事实 | 更新后的 Draft |
| P5 | 做事实、Boundary、Hook、职责和 Reference Gate 审计 | FORBIDDEN=0、Hook 全兑现；若使用 Reference，模态/可观察性/原创性/采用四项全 PASS | Draft 中 Audit、Review Summary、Approval Preview |
| P6 | 保留 Draft、生成 LOCKED 并登记交接 | LOCKED 与批准版本一致；完整性值只登记 manifest/state；下一站是 Script Studio | `02_narrative_plan_LOCKED.md`、更新后的 manifest/state |

## 三条硬检查

1. 发现新增事实、未决 CONDITIONAL、视听幻觉或参考视频实质复制：立即停止，不批准。
2. 任何 LOCKED 变更必须创建 Change Request，不能直接覆盖。
3. P6 完成只登记 Script Studio，不自动运行下游。
